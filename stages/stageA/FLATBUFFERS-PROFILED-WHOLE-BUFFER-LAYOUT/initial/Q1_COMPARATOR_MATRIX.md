# Q1 comparator matrix

This is the frozen executable union for Stage A. Each row is an individually realizable current-native plan/configuration; the union is evaluated after the same-object checker and on the same denominator. The tiny exhaustive oracle is a ceiling only.

| ID | Executable method | Native action family | Profile use | Bound/budget | Full-cost treatment | Role |
|---|---|---|---|---|---|---|
| B0-GEN | pinned generated object-API `Pack` / generated direct default | current generated native path | none | native default | all measured | mandatory default baseline; ineligible output if presence/identity digest changes |
| B0-STABLE | deterministic stable legal topological node order plus generated field order | complete fixed direct-builder grammar, one deterministic plan | none | linear | all measured | mandatory native plan |
| B0-HOT | hot-first ready-node heuristic with deterministic tie break | same legal ready actions | frozen training profile | linear/heap | all measured | mandatory profile-aware current-action heuristic |
| B0-CFG | union of applicable `DedupVtables` on/off, presence-consistent `ForceDefaults`, default/size-matched capacity | individually realizable current configs; never a fictional simultaneous arm | same as underlying plan | full grid fixed before heldout | allocator/reallocation included | strongest current config union |
| B1-LOCAL | exact local table field-order/subtree DP, then stable global composition | same native actions but no cross-subtree reuse closure | frozen profile restricted to subtree | same local state cap | all measured | direct subtractor; cannot establish N2 |
| B2-GENERIC | generic bounded full-state planner/enumerator with exact replay cost but no FB-specific reuse-closure quotient | same native action set and same cap/beam/timeout | frozen profile | exactly candidate-matched | all measured | strongest same-budget algorithmic comparator |
| B3-EXACT | exhaustive public-builder grammar | complete | frozen profile | tiny instances only | validation cost reported separately | exact ceiling; never deployable baseline |
| CAND | FB-RCFDP | globally couples legal construction order, table field order, permitted string/alias choices and current config arm through exact position/reuse state | frozen training profile | unpruned tiny; preregistered bounded frontier/beam and deterministic stable fallback on natural objects | all measured, including fallback | candidate N2 |

## Same denominator

Every eligible row receives the same immutable identity graph and emits one ordinary native buffer with the same identifier. It is scored on:

- raw buffer bytes;
- exact frozen weighted address distance (proxy only);
- measured native reader/profile-trace latency, cold and warm;
- profile extraction, planner, builder, verifier and reader CPU/wall;
- peak RSS, allocation/reallocation and temporary bytes;
- state/backpointer counts and fallback rate.

An arm failing the verifier, generated reader, presence/value/vector/key/header digest or explicit alias classes is ineligible rather than credited with better bytes/runtime. Generated `Pack` is especially audited because object-API pack may erase binary presence or alias provenance.

## Candidate action residual

Candidate useful transitions must be outside the actions selected by B0-GEN/B0-STABLE/B0-HOT/B0-CFG and outside the frontier found by B1/B2 under the same budget. Merely choosing a different stable/topological order, sweeping stock flags, applying a local table heuristic, or invoking an opaque solver is direct absorption. The residual is only a strict natural-object reuse-closure state quotient plus a held-out executable frontier point.

Retained residual action coverage is:

`natural candidate transitions whose normalized state has >=2 legal globally distinct predecessor plans and whose selected continuation differs from every B0/B1 plan / all candidate transitions`.

The preregistered minimum is `10%` overall and reported by stratum. Singleton states or no strict quotient compression on natural objects fires the killer.

## Positive bar

Cost alone cannot create mathematical Pareto novelty. A positive point needs a real raw-byte or measured-access primary benefit, no worse same-object semantics, and all added profile/planner/build/verify/read costs inside the registered budget. Both held-out p50 and p90 must retain a residual against the full executable union. Stage A support, if any, remains `PRELIMINARY_SUPPORT__NOT_FALSIFIED` pending independent gate review.
