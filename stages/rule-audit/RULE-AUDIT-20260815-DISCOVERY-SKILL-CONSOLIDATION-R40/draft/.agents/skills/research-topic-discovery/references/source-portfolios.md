# Source portfolios and query roles

Use this reference when a Discovery lane chooses what to inspect. It changes search allocation, not admission standards.

## Four source roles

Within the frozen retrieval budget, cover the roles needed by the opportunity instead of issuing generic topic queries:

1. `ANCHOR`: the exact paper, artifact, workload, benchmark, specification, or implementation locus that defines the problem.
2. `CURRENT`: first-party current documentation/source/configuration and the strongest deployable/current comparator union.
3. `CONTRARY`: the most obvious same-object collision, generic kernel, null explanation, negative result, or stronger simple baseline.
4. `ESCAPE`: a mechanism-first query for work that solved the bottleneck under different terminology; use recent work and one-hop genealogy when decision-relevant.

Do not require all four roles for every pre-RQ seed. The anchor role is required before source closure; the other roles become mandatory only at the stage specified by `ROLE_DISCOVERY.md`.

## Lane viewpoints

- S1: boundary contradiction, assumption failure, or target-specific semantic mismatch.
- S2: downstream bottleneck transfer with a non-separable decision consequence; treat product/API/configuration combinations as high-risk negatives.
- S3: natural or canonical structure tied to an estimand, stable law, or usable action.
- S4: objective/constraint change, measurement validity, benchmark bias, Pareto boundary, or formal consequence.
- S5: scale/online/approximation/data-structure failure with fixed object, information, and guarantee.
- S6: direct algorithm/software residual with a target-specific action or complexity/guarantee delta.

These are viewpoints, not quotas. Any lane may route a measurement, benchmark, formal, or algorithmic opportunity when its evidence fits.

## Saturation handling

- Use exact five-field identity or frozen direct collision for exclusion.
- Use repeated poor query yield or repeated generic/current absorption only to de-weight a source family for the next frozen cycle.
- Never turn broad platform, ISA, project, cache/index/allocator/compiler, or opportunity-family similarity into permanent cooldown.
- Preserve `RELATED_ONLY` routes for a different action, estimand, endpoint, guarantee, or full-cost boundary.

## Query-yield note

For each query role, record `core / adjacent / off-topic / exact-history / current-fatal / anchorable-unresolved`. A role dominated by off-topic or survey results should be rephrased mechanism-first next cycle. A role dominated by exact/current fatal evidence is useful negative evidence, not a failed search.
