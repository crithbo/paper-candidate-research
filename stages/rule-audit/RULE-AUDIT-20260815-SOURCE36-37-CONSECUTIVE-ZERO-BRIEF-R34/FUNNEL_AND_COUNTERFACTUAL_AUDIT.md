Source37 changed both stage-order enforcement and source-role hints, and it did not use an identical paired seed set. Therefore the observed increase cannot be attributed solely to stage separation.

## Why the stage-order PASS is necessary but insufficient

The registered `PASS_ALL_SELECTED_SEEDS` is mechanically true. It only checks seeds that were selected. Source37 S3 selected zero seeds because it required an exact public carrier/version before RQ formation. That is a vacuous pass: `DISCOVERY_RQ_CANDIDATE.md` requires only a tentative public object/source origin and a minimum public carrier/oracle route at RQ time; exact identity/version belongs to the later Question Card raw gate.

S4 demonstrates the opposite failure. It correctly formed three RQ families first, but each remained an abstract placeholder such as “one fixed versioned benchmark artifact.” The source ledger remained empty and the source-closure queue was also empty because the Question Card was incomplete. This is circular: the missing public artifact/source locus is exactly what `SOURCE_CLOSURE_QUEUE` exists to close between RQ and raw.

## OFST: healthy recall or weak generic topic?

The OFST row is **healthy raw recall with high unresolved precision risk**, not a clean-brief success and not a generic false positive already proven:

- It froze a same-object weighted-transducer relation, a natural CMUdict carrier route, current OpenFst loci, initial full-cost dimensions, a minimum falsifier and a finite closure plan.
- It did not claim novelty, absence, Q2, a result, or a clean brief.
- Independent closure found real mutable/static action surfaces and adjacent dynamic-WFST work, but no direct same-object/same-guarantee collision.
- It also failed to close current-main union, two exact before/after relations and a finite relation/lookup oracle, so it correctly stayed `NOT_ADMITTED_UNFROZEN`.

Thus the raw gate behaved as a bounded-debt boundary. The sample is still `n=1`; it proves neither good clean-brief precision nor systematic generic-graph contamination.

## Model-capability counterfactual

Blanket replacement of all six Discovery sessions with a stronger model is not supported by the evidence:

- S3/S4 performed no targeted retrieval, so no model could infer a defensible exact carrier/current source from absent evidence.
- The existing model already produced a well-formed OFST raw once it had concrete OpenFst/CMUdict anchors.
- The hard remaining judgments—same-object action atomicity, generic-kernel subtraction, current-union mapping and finite oracle design—are reasoning-heavy and may benefit from a stronger model.

The least-confounded response is therefore a **selective depth escalation**, not a blanket breadth upgrade: retain `gpt-5.6-terra / medium` for six-lane seed/RQ breadth, then send at most two precommitted carrier-closure packets across the whole Source40 cycle to `gpt-5.6-sol / high`. The stronger model receives a neutral frozen packet and cannot change RQ, backfill, score novelty or write a brief. This tests model value exactly where downstream evidence is missing without increasing lane count or making model prestige an admission signal.

## Resource-compliance diagnosis

The OFST acquisition path made 16 calls against a frozen cap of 8. Authentication rejects, 404s and zero-persistence calls still consume attempts. The second group of eight therefore could not be treated as a fresh budget. This is an execution-accounting defect, not a resource-localization-root failure and not scientific evidence.

The final inventory also retained three files while leaving `root_measurement.logical_bytes=0`, `measurement_complete=false` and `finalized_at=null`. The entries and hashes are present, so provenance is not lost, but the durable inventory was not mechanically finalized. Any next source-closure scheduler must increment one global counter **before** every acquisition call and require inventory finalization before handoff.
