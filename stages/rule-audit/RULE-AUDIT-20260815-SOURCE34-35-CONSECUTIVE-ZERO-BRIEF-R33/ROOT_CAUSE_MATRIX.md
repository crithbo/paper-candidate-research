## Rule-versus-execution finding

The current authoritative rule already separates the stages:

- seed exclusion is limited to exact identity, certified terminal reuse, definitional object/guarantee mismatch, network-security exclusion, or a generic shell;
- each selected seed forms 2–3 same-object RQ variants before targeted evidence;
- the Question Card raw gate freezes a bounded minimum contract;
- complete current union, strongest subtractor, full small witness, implementation and result remain closure debt.

Therefore R33 does **not** recommend lowering the raw gate. It recommends one cycle that mechanically enforces the existing separation and makes identity/cooldown decisions auditable.

## Healthy abstention versus avoidable pre-raw loss

Healthy abstention includes current API/source absorption, a generic wrapper/solver, or a terminal negative witness that demonstrably transfers to the new identity. Avoidable loss includes:

- demanding raw-card evidence before an RQ may be articulated;
- treating a common paper/tool/ISA/carrier as exact identity;
- requiring a new public evidence delta merely to formulate a distinct RQ;
- applying an algorithmic constructor test to measurement, benchmark or formal contribution types;
- treating `UNRESOLVED_BOUNDED` as if it were a scientific negative.

## Source35 shadow disposition

R32 prescribed prospective shadow because the active veto might be over-pruning. Source35 supplied no base raw to which the check could apply. It therefore cannot validate the check, but it does establish that continuing the shadow would add ceremony without information at the current pre-raw bottleneck. R33 recommends `NON_PRODUCT_COUPLING_SURVIVAL=OFF` for the Source37 pilot. This does not declare the scientific idea false; it only removes an uninformative assignment-local diagnostic.
