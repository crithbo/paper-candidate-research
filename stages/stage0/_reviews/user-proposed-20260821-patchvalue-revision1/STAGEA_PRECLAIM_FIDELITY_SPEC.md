# Stage A preclaim fidelity specification — not authorized to run

## Gate purpose

Before any claim-bearing measurement, construct one tiny legal public coding-state witness and evaluate only the contract, not a scientific advantage. Required manifests are defined by `STATIC_CERTIFICATE.yaml`.

## Expected checks

1. Common prefix identity: task/base revision, patch, events, agent state, prompt, tool outputs, model/server/decoder configuration, call index and evaluator revision hashes match.
2. Mutable isolation: worktree/container/process/tool/evaluator identities differ across arms; every permitted shared identity is immutable.
3. Treatment: `A=0` freezes; `A=h` follows the registered native call-slot grammar; early terminal and all failures remain explicit outcomes.
4. Firewall: evaluator has no access before the arm is frozen and no label returns to state choice or action selection.
5. Cost: all branch, clone/reset, tool, evaluator, storage and failure costs are retained.

## Preclaim failure conditions

Failure of any check is a mechanism failure, not a performance data point: stop the primary continuation-effect claim under `STOP__CAUSAL_REPLAY_RELABEL_OR_NONIDENTIFIED_BRANCH_EFFECT`. A successful fidelity check is only a contract precondition; it does not establish a positive effect, allocation gain, Q1 result or Stage B eligibility.

## Bounded later falsifier

After the fidelity gate, a repository-disjoint public-state study must compare the frozen union under equal total call budget. It must stop the deployment/allocation claim if lower-bound effects have no support, no-gain/harm layers are concealed, or full cost removes a Pareto relation. This task has not authorized that work.
