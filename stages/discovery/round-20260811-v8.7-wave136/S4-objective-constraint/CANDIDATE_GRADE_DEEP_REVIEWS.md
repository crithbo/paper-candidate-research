# Candidate-grade N3 deep reviews

## R01 — tail prediction from low-order task statistics: `STRUCTURAL_DROP__EXISTING_CHARACTERIZATION_AND_BOUNDARY`

The reported rule is limited to high-load scale-out requests with barrier synchronization; the same source already supplies the mean/variance explanation and the p99 prediction. The stated support spans model and measurement cases, not independently frozen, heterogeneous natural workload families with controlled topology, service-time, and admission differences. The cliff could be a queueing/load effect rather than a stable new natural structure. A legitimate 72-hour killer would require pre-registered traces, a fixed p99/error metric, and leave-one-workload-family-out prediction; this is a characterization re-run, not a new mechanism. No union-external utilization mechanism is frozen.

## R02 — integrity-tree workload locality: `STRUCTURAL_DROP__CURRENT_EXPLANATION_AND_CONSTRUCTOR_COLLISION`

The object is a secure cloud disk with unchanged integrity/freshness semantics. The current paper first characterizes the realistic cost pattern and then supplies Dynamic Merkle Trees as the exploitation mechanism. A new claim needs a cross-device, cross-workload invariant beyond the existing locality/pattern explanation; none is named. Controlling read/write ratio, locality, metadata cache state, storage medium, and recovery is essential. The full denominator includes tree creation, hash/metadata I/O and recovery. The finite killer is therefore defined but not run: fail if a holdout device/workload family loses the observed ordering after those controls. This is direct collision, not a readiness drop.

## R03 — KV-separation GC three-way cliff: `STRUCTURAL_DROP__CURRENT_EXPLANATION_AND_NATIVE_CONSTRUCTION`

The first-party source itself identifies the CPU-versus-I/O GC trade-off as the explanation for the throughput/tail/space tension and provides AegonKV's native coordination construction. It has not established a new stable law across independently collected storage engines, devices, and workload families after controlling value size, update skew, occupancy, and GC trigger. Any attempted action is already the current direct coordination/lock construction or changes the storage engine. A 72-hour falsifier is available in principle—pre-register several public KV traces and require the same cliff after all construction and GC costs—but no novel N3 utilization rule remains.

## R04 — mobile-SoC energy proportionality: `STRUCTURAL_DROP__CHANGED_DEPLOYMENT_OBJECT_AND_CONFOUNDING`

The measured differences compare a mobile-SoC cluster against traditional edge servers. Hardware, capacity, thermal regime, and deployment cost all change, so the apparent Pareto cliff is not same-object evidence. The paper's gaming/transcoding/inference suite is valuable natural characterization, but it does not freeze a stable invariant across a common fixed service object. A valid killer would normalize output quality, capacity, power measurement boundary, embodied/device cost, and identical input traces before testing workload-family holdout. Until then, it is an architecture comparison, not an N3 opportunity.

All four deep reviews explicitly separate data availability from admission. They fail direct collision, cross-object stability, or same-object control—never lack of implementation/result/resource.
