# Unique N3 opportunity families

Six distinct observation families were screened, with four proceeding to the stronger N3 test. They remain raw/deep-review entities only: no stable cross-object rule passed admission.

| id | data / metric contract | current explanation or collision | required full-cost denominator |
|---|---|---|---|
| R01 | request p99 under a fixed barrier-workload model; task response mean/variance | already presented as a high-load predictor, not a new invariant | instrumentation, queueing, CPU, end-to-end latency |
| R02 | identical integrity/freshness semantics on secure disks | Dynamic Merkle Trees already exploit workload patterns | tree construction, metadata I/O, hashing, reads/writes, recovery |
| R03 | equivalent KV operations and storage occupancy | AegonKV already names the GC CPU/I/O explanation and supplies a native construction | foreground I/O, GC CPU/I/O, coordination/RDMA, space amplification |
| R04 | fixed application output-quality metric and end-to-end service level | architecture comparison confounds the observation with changed deployment hardware | device/server embodied energy, throughput, tail latency, monetary cost, quality |
| R05 | same inference output/SLO across real serving traces | a live autoscaling controller is the published contribution | scale action, parameter movement/cache, GPU time, tail latency |
| R06 | fixed accuracy target or latency target on Microsoft-derived traces | policy selection is explicitly the current mechanism | policy-training/selection cost, accuracy, latency, resource cost |

The natural carriers are real/publicly reported, but natural availability alone cannot turn an already-explained curve into an N3 result.
