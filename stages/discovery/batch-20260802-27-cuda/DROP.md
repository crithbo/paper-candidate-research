# Wave 27 consolidated DROP register

Each row names a distinct object and a same-semantic public implementation or benchmark anchor. `DROP` is a Discovery paper-kernel judgment, not an experiment.

| ID | Object and public anchor | Decision / strongest-union boundary | Complete-cost boundary |
|---|---|---|---|
| GPU-SPMV-SKEW-ROWTILE | Exact CSR SpMV for degree-skewed SuiteSparse matrices; cuSPARSE and merge-path SpMV | `DROP`: row splitting/merge-path/warp assignment already span the action space; a degree threshold only selects them. | inspection, partition descriptors, scans, reductions, format conversion, launch, and fallback. |
| GPU-SPTRSV-LEVELBUCKET | Exact sparse triangular solve with uneven level sets; hypre and cuSPARSE | `DROP`: level scheduling, synchronization and row bucketing are established; no new invariant/bound beyond scheduler selection. | analysis, level construction, dependency state, synchronization, workspace, and refactorization. |
| GPU-SORT-SKEWSPLIT | Distribution-adaptive radix/sample sort on public sort benchmarks | `DROP`: it is a renamed radix/partition scheduling problem; CUB/RadiK-type union and historical top-k-radix nucleus cover it. | sampling, histogram, splitters, exchange, passes, temporary storage, and stability. |

| GPU-DYNBFS-SSD | Exact update-sensitive BFS with GPU/SSD residency on temporal graph streams | `DROP`: historical dynamic-BFS repair nucleus is unchanged; residency only adds a cache policy. | update ingest, invalidation, I/O, frontier materialization, repair/rebuild, and query latency. |
| GPU-REDUCE-EXPSKETCH | Reproducible sampled reduction with exponent sketches | `DROP`: changes the known reproducible-reduction nucleus only by approximate bins; no independent target guarantee was retained. | exponent scan, sketches, seed/error, exceptional values, rounding, spill, and fallback. |

No candidate is stopped because a GPU is unavailable. The historical prohibited nuclei and direct union coverage, not tooling, cause the DROP decisions.
