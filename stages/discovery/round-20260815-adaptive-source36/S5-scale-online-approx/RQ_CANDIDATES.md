# Source36 RQ candidates

## RQ36-A — LLVM target backend

Can a target-specific, invariant-preserving register-allocation/scheduling constructor offer a bounded-recourse or certified Pareto guarantee for a fixed target ABI and machine-code endpoint, beyond LLVM's current complete allocator/scheduler union?

Minimum falsifier: the current union already exposes an equivalent complete target-native action, or the proposed action is only pass/configuration selection.

## RQ36-B — Gemmini

Can a same-ISA, same-result accelerator mapping constructor supply a nontrivial target-specific guarantee without being merely a Gemmini elaboration/runtime parameter choice?

Minimum falsifier: the primary object is the project-owned full-stack generator/configuration, rather than a distinct stock-native partial primitive.

## RQ36-C — Calyx

Can a stock-checkable Calyx resource-sharing action be made bounded-recourse while preserving the same control program endpoint?

Minimum falsifier: the action is generic compiler scheduling or a paper/tool-owned whole constructor rather than a target-specific primitive.
