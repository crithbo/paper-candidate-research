## Current-upstream reality check

AMD's current ROCprofiler documentation affirmatively describes the important semantic split: dispatch counting serializes target-device kernels, while device counting covers a time range without kernel attribution; profiles are agent-specific and immutable.  NVIDIA's current guide affirmatively describes serialization, replay/cache controls, and the fact that host timers/CUDA events include tool overhead under Nsight Compute.  These are not absence claims.  Current flag/config unions checked include ROCprofiler counter groups, multi-pass rows, tracing, collection periods and PC-sampling options; and Nsight replay mode, cache control, replay buffer/matching and target-process controls.  Therefore neither remaining research question may be recast as “the tool lacks an option.”

## Bounded rescreen gate

Either R1 or R2 may only re-enter a future assignment with all of the following pre-frozen: a public versioned natural concurrent-workload corpus; fixed output/quality semantics; pre-specified tail/energy/utilization estimand; sampling/thermal/cache/clock/profiler confounds; current fair profiling union; collection-to-analysis full cost; and a held-out falsifier that can eliminate any claimed measurement-consequence law.  This is a missing evidentiary contract, not a claim about academic potential or execution resources.
