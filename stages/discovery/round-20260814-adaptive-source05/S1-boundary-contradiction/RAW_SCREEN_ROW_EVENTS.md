# RAW_SCREEN_ROW_EVENTS

Problem-first raw admission is not a proposal decision. It deliberately precedes whole-union closure. Each row has a fixed public interface and a current first-party anchor; the action promise is non-binding until depth.

| Row | Opportunity family signature | Fixed interface / boundary problem | Current first-party anchor (snapshot 2026-08-14) | Non-binding action promise | Raw status |
|---|---|---|---|---|---|
| R01 | `LINUX_RSEQ__PREEMPT_SIGNAL_ABORT__POST_COMMIT_PERCPU_UPDATE__FIXED_RSEQ_ABI` | An rseq critical section has an ABI-defined pre-commit abort interval and a post-commit success interval. The opportunity question is whether a fixed set of per-CPU update traces admits a complete placement/shape construction that reduces abort/retry work without changing success/abort observations. | [Linux rseq documentation](https://docs.kernel.org/userspace-api/rseq.html); [current kernel rseq.c](https://github.com/torvalds/linux/blob/master/kernel/rseq.c); [current selftest header](https://github.com/torvalds/linux/blob/master/tools/testing/selftests/rseq/rseq.h). | Choose boundaries and recovery descriptors for a fixed update trace, not scheduler policy. | `DEEP_DIVE_REQUIRED` |
| R02 | `ELF_TLSDESC__COMPILER_RELOCATION__LINKER_GNU2_TLS_TAG__LOADER_RESOLUTION_COST__FIXED_ELF_ABI` | The compiler emits TLS address materialization, the linker preserves/relaxes relocation semantics, and the dynamic loader resolves a descriptor. The question is a same-ELF-ABI joint construction over legal descriptor vs conventional access forms under link/load cost. | [GNU ld current options](https://sourceware.org/binutils/docs/ld/Options.html) documents `R_X86_64_TLSDESC_CALL` and `--gnu2-tls-tag`; [LLVM upstream](https://github.com/llvm/llvm-project/tree/main/llvm/lib/Target) is the compiler source anchor; [binutils upstream](https://sourceware.org/git/?p=binutils-gdb.git) is the linker-source anchor. | Choose a whole-program access-form/relocation assignment while preserving symbol, relocation, loader and ABI semantics. | `DEEP_DIVE_REQUIRED` |
| R03 | `RISCV_ZICFILP__ELP_STATE__INDIRECT_BRANCH_TARGET_LPAD__FIXED_CFI_SEMANTICS` | Zicfilp introduces expected-landing-pad state at an indirect transfer. The potential mismatch is between CFG/code-generation placement and hardware state validation under fixed CFI semantics. | [Ratified RISC-V CFI specification](https://docs.riscv.org/reference/isa/unpriv/unpriv-cfi.html); [LLVM RISC-V target source](https://github.com/llvm/llvm-project/tree/main/llvm/lib/Target/RISCV); [GCC RISC-V source](https://gcc.gnu.org/git/?p=gcc.git). | Jointly choose legal indirect-target/landing-pad representation for a fixed CFG, not a CFI mode switch. | `DEEP_DIVE_REQUIRED` |
| R04 | `JVM_CONDY__BOOTSTRAP_RESOLUTION_PUBLICATION__CLASSFILE_CONSTANT_POOL__FIXED_JVMS_RESULT` | `CONSTANT_Dynamic` resolution joins class-file producer and VM resolver; success/error caching and bootstrap execution are semantically constrained. | [JVMS 26](https://docs.oracle.com/en/java/javase/26/docs/specs/jvms/index.html); [JVMS class-file form](https://docs.oracle.com/en/java/javase/26/docs/specs/jvms/jvms-4.html); [OpenJDK upstream](https://github.com/openjdk/jdk). | Construct a class-file/bootstrap dependency arrangement while preserving per-constant value/error semantics. | `DEEP_DIVE_REQUIRED` |
| R05 | `LINUX_FUTEX_WAITV__MULTIWAIT_CHECK_SLEEP__WAKE_INDEX_VISIBILITY__FIXED_FUTEX2_UAPI` | `futex_waitv` atomically verifies a wait set before sleeping and returns a woken index. The seam is user-level wait-set representation versus kernel publication of the observed wake. | [Kernel futex2 documentation](https://docs.kernel.org/userspace-api/futex2.html); [Linux upstream](https://github.com/torvalds/linux/tree/master/kernel/futex); [current futex selftest](https://github.com/torvalds/linux/blob/master/tools/testing/selftests/futex/functional/futex_waitv.c). | Choose an equivalent native wait-set representation for a fixed set of futex words and returned-index contract. | `DEEP_DIVE_REQUIRED` |
| R06 | `AARCH64_GCS__CALL_RETURN_GUARDED_STACK__UNWIND_TRANSITION__FIXED_AAPCS64_SEMANTICS` | Guarded-control-stack call/return state meets compiler frame/unwind construction. The boundary is a fixed AArch64 ABI and observable unwind/return behavior, not an attribute choice. | [Arm ABI specifications repository](https://github.com/ARM-software/abi-aa); [LLVM AArch64 source](https://github.com/llvm/llvm-project/tree/main/llvm/lib/Target/AArch64); [GCC AArch64 source](https://gcc.gnu.org/git/?p=gcc.git). | Choose a whole call-graph state-preservation construction under the same guarded-stack ABI. | `DEEP_DIVE_REQUIRED` |

No row is a repeat of Source01–04 identities (LLVM coroutine, Wasm engine async ABI and their adjacent closures), mature cache/index maintenance, or generic prologue/RA cleanup. Raw status means “worth bounded closure,” not acceptance.
