# Carrier-first raw screen

Six fresh identity candidates were screened across the requested rotation. The carrier and stock semantic oracle precede any mechanism. A “law” is an estimand with falsifier, not a result.

| ID / rotation | Carrier & oracle first | Pre-registered opportunity/law and confounds | Current union / strongest subtractor | Pre-outcome disposition |
|---|---|---|---|---|
| S18-01 public operator release: ONNX opset semantic history | Immutable ONNX release tags/opset documents; `ModelProto` plus ONNX checker is a stock semantic oracle. ONNX specifies immutable operator-set snapshots and model imports [versioning](https://onnx.ai/onnx/repo-docs/Versioning.html). | Estimate whether semantic operator additions/updates form stable operator-cohort transitions across release-adjacent public models, controlling opset, backend, precision and model family; falsify on held-out opset transitions. | A target compiler’s importer/lowering union is not one native union: it depends on the selected backend. Candidate must not treat a standard’s version history as a compiler residual. | `NOT_ADMITTED_UNFROZEN__NO_SINGLE_CURRENT_NATIVE_UNION`. |
| S18-02 cross-accelerator workload: MLPerf Tiny releases | Official v1.3/v1.4 result releases expose fixed task/model/quality methodology over MCU/vector/NPU platforms [v1.4](https://mlcommons.org/2026/07/mlperf-tiny-v1-4-results/) [v1.3](https://mlcommons.org/2025/09/mlperf-tiny-v1-3-results/); task accuracy is oracle. | Estimate phase/operator-shape evolution associated with cross-accelerator ranking inversions, controlling benchmark version, scenario, accuracy target and energy method; falsify on next release. | A compiler/mapping union is submitter/platform-specific, while the requested mechanism would otherwise be a mapping selector. Registry also has active MLPerf/DCGM Stage0; no substitute identity entered. | `EXCLUDED__ACTIVE_MLPERF_BOUNDARY_AND_SELECTOR_RISK`. |
| S18-03 compiler-input corpus: LLVM test-suite release history | LLVM tags and tests are versioned, but the contract rejects tests as natural carriers absent independent workload evidence. | A release-history compiler corpus could estimate IR/loop/alias regime shifts, controlling target and optimizer. | No independent natural carrier or stock application oracle was frozen. | `EXCLUDED__TEST_NOT_NATURAL_CARRIER`. |
| S18-04 compiler-input corpus: ONNX model release panel | Official model serialization has semantic version fields and checker rules, but the bounded review did not freeze an official checksum-pinned multi-release model panel. | Estimate operator/shape/change-phase recurrence across model versions; held-out later model releases. | Same exact missing immutable model panel as S18-01’s attempted carrier specialization; no repeat source-only closure. | `DORMANT_SOURCE_SATURATED_UNFROZEN__CARRIER`. |
| S18-05 architecture trace: ROCProfiler history | ROCm documents versioned tracing tooling, but its examples are demonstration applications; trace output alone is not a natural workload carrier [ROCProfiler](https://rocm.docs.amd.com/_/downloads/rocprofiler/en/latest/pdf/). | A public HIP application trace history might estimate phase-local resource behavior, controlled for GPU/ROCm/counter set; falsify on later trace releases. | No immutable independently generated application trace panel, and an action would otherwise be scheduling/config selection. | `NOT_ADMITTED_UNFROZEN__CARRIER_AND_NONCONTROLLER_ACTION`. |
| S18-06 architecture telemetry: Nsight Compute report history | Nsight Compute documents versioned report/metric output, including CSV, but a profiler report is a measurement artifact rather than a natural workload [CLI](https://docs.nvidia.com/nsight-compute/2022.4/pdf/NsightComputeCli.pdf). | Estimate metric/phase transition stability only with a separately versioned natural workload and fixed metric set; falsify on held-out release. | No public immutable workload/trace chain or union-external offline construction was frozen. | `NOT_ADMITTED_UNFROZEN__TELEMETRY_NOT_NATURAL_CARRIER`. |

All six identities are distinct from Source17’s PyTorch/TensorFlow/Keras/TensorRT/Vitis/MIGraphX cards; no security-related opportunity was considered.
