# Unique opportunity family

## UOF-220-01 — versioned Debian Contents path ownership relation

- **Exact semantic object:** for fixed `(snapshot timestamp, suite, component, architecture)`, the complete optional Contents relation mapping each normalized archive-relative pathname to its specified qualified package-name list.  Header treatment follows the documented reader behavior; it is not a new package-installation, dependency-solving, or delta-transport task.
- **Natural carrier and hash route:** select 20–50 chronological timestamps from Debian Snapshot; retain signed `InRelease`/`Release`, the Release-listed SHA-256 and byte size for `Contents-<arch>.gz`, and the corresponding snapshot URL.  The Debian repository format documents timestamp-addressable snapshots and Release hash listings.  This is a future finite Stage A acquisition plan, not data acquired in Discovery.
- **Phenomenon schema:** on held-out timestamp blocks, measure (i) pathname→owner-list insert/delete/change rate, (ii) longest-common-prefix/run distribution after a layout-independent canonical pathname order, and (iii) owner-list recurrence, conditioned on component, architecture, suite cadence, package-count delta, and release/date.  The required law is a replicated residual over those controls, not a correlation from one release transition.
- **Candidate action if law holds:** construct the complete Contents mapping using a deterministic joint prefix/owner-list factorization selected from the frozen relation, then materialize a standards-conforming Contents file.  The action is deliberately not only a reorder, compression flag, external cache, or delta.
- **Minimal witness:** two legal complete constructors given the same normalized mapping: stock full scan/generation versus a deterministic factorization/materialization whose decoded mapping is byte-insensitive but relation-identical under a stock reader.  A witness is not yet frozen because the actual Debian archive production constructor/configuration and the proposed representation's permitted output boundary were not fixed.
- **Current union:** (a) Debian Archive Kit (dak) runs the Debian archive; (b) APT `apt-ftparchive` exposes `contents` and `generate`, configuration-driven Contents output, database/cache options, compression configuration and incremental file-change checks; (c) repository format permits multiple index compressions and `*.diff` delivery; (d) apt-file obtains/searches Contents through APT index-target configuration and treats Contents as optional.  This union is strong, but the exact archive-production config/revision and all dak publishing paths were not frozen here.
- **Decision:** `NOT_ADMITTED_UNFROZEN`.

Reason: the natural before/after law has not been established under the stated controls, the whole action witness has not been made standards/reader-exact, and the current Debian Archive/dak configuration union was not completely frozen.  These are evidence-closure gaps, not negative performance, implementation, resource, or AI-readiness evidence.
