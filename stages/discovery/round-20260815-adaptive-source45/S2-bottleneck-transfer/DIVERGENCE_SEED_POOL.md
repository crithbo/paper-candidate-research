# Divergence seed pool — non-evidentiary

| Seed | Creative engine | Prompt |
|---|---|---|
| S01 | bottleneck transfer | When sparse-resource residency removes dense allocation, does binding/update cost create a new same-resource constructor? |
| S02 | interface inversion | When rectangular target copies replace element-wise transfer, can shape/dependency construction be an algorithm rather than an API call? |
| S03 | lifecycle inversion | When a portable deep copy has no hidden movement, can mirror/layout/lifetime jointly change same-view full cost? |
| S04 | adversarial subtraction | Does each potential construction remain after subtracting the current native API’s declared actions? |
| S05 | information manipulation | Is the proposed input beyond the same program/view/command information available to the deployment baseline? |
| S06 | guarantee-first | Would a formal cost/recourse guarantee still be target-specific after removing names of runtime/API knobs? |

S01–S03 were selected before outcome evidence. Seeds are not raw or scientific evidence.
