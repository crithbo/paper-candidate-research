## Research question

For a fixed legal SystemVerilog design and fixed Verilator scheduling semantics, can a compile-time constructor emit dependency-closed MTask bundles and an epoch-bound dispatch representation so that online profile observations permit bounded-recourse rebinding while preserving the exact simulation trace and providing a conditional load-imbalance/overhead guarantee against the fair static MTask union?

## Canonical research claim package

- Exact object and same-function contract: fixed SV design, `--threads` model, same generated-model interface and same scheduling-visible outputs (including trigger/NBA ordering).
- Natural carrier: version-pinned public CVA6 RTL and its documented Verilator regression/simulation route.
- Atomic action: replace a completed static MTask-to-thread assignment only at an `eval()` epoch boundary by rewriting a pre-emitted dispatch table over dependency-closed bundles; preserve all predecessor, trigger and NBA constraints.
- Information: only profile information generated by the same previous epochs; no offline future trace or omniscient scheduling oracle.
- Fair baseline: current serial evaluation, default/current static threaded `V3Order`/`V3Partition` construction, MTask-count setting, and Thread-PGO under equal threads/configuration and profile history.
- Target guarantee: exact semantic trace equivalence plus a formal per-epoch recourse budget; any approximation/competitive statement is conditional on an explicit stationary-window assumption and compares full runtime overhead to the static union, not to offline OPT.
- Full cost: Verilation/constructor time, generated code bytes, generated-model RSS, dispatch-update CPU/bytes, synchronization, profile overhead, simulation wall time, peak RSS and no-gain cases.
- Direct subtractor: current static partition/assignment plus Thread-PGO; it lacks the proposed complete epoch-bound rebinding action according to current official internals, subject to Stage 0 source recheck.
- Minimum falsifier: a two-bundle SV dependency/NBA witness for which rebinding changes trace order, violates a predecessor/trigger invariant, exceeds declared recourse, or fails to beat/equal the static union under the stated condition.

## Mechanism and competing explanations

Mechanism: grouped, dependency-closed bundles expose a bounded action space in which measured imbalance can be reduced without moving any action across a semantic edge.  The main competing explanation is that static Thread-PGO or MTask-count configuration already captures the useful improvement; a second is that dynamic dispatch/synchronization costs eliminate gain.  Both are explicit baseline/no-gain outcomes rather than omitted costs.

## Current-upstream reality check

- Source snapshot: Verilator current `master` documentation consulted 2026-08-14; Stage 0 must pin an exact commit.
- Official documentation/source: `docs/internals.rst` names `V3Sched::schedule`, `V3Order`, `V3Partition`, static thread assignment/order, fragmentation, and the runtime profiling context.
- Flags/configurations checked: `--threads`, `--threads-max-mtasks`, `--prof-exec`, `--prof-pgo`, thread-DPI modes and default single-thread behavior.
- Contrary evidence: Thread-PGO and static MTask tuning are current mechanisms and are part of the baseline union.  The docs’ discussion of possible runtime repack is not used alone as absence evidence; the source/documented present static construction is the sole frozen comparison point.
