## Current-upstream reality check

Current `torch.compile` documentation already specifies guards, automatic dynamic-shape recompilation, explicit `dynamic=True`, dynamic-source annotations, diagnostics, and the bounded recompile-to-eager behavior. A proposal that merely marks shapes dynamic, changes a guard/cache policy, records graph breaks, or adds generic fallback diagnostics is therefore absorbed/current or a wrapper.

Current TorchAO documents composability with `torch.compile`, int4/dynamic activation configurations, allowed group sizes and packing formats. These public fields are configuration/representation surfaces, not evidence that a fresh semantic compiler action exists. A layout certificate or repacking proposal would need a specific current source locus that wrongly rejects an otherwise legal call; none was identified.

Current CUDAGraph Trees explicitly handles dynamic shapes by rerecording per shape, offers skipping dynamic graphs and recommends padding when useful. Therefore the proposed capture-island formulation has no admission path without a separately evidenced low-bit semantic conflict. Current Triton sources also make generic ragged/masked handling available; masking a tail is not itself a contribution.
