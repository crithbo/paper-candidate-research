# Source102 primary RQ candidates

## RQ-S102-01 — SQLite NGQP

For a fixed SQLite version, database schema, `sqlite_stat*` contents, SQL query, and query-result semantics, can a target-specific bounded join-plan construction improve the plan-quality/prepare-cost frontier beyond the current NGQP N3 plus star-query composition?

Same-object endpoint: identical SQL result and supported plan-stability contract. Full cost: preparation CPU/RSS, statistics maintenance, planning/search state, generated bytecode, query CPU/I/O/latency. Minimum falsifier: the candidate reduces to generic join-order search, a statistic/configuration change, or the already documented N3/star heuristic union.

## RQ-S102-02 — CMake Unity Build

For a fixed CMake target, compiler/toolchain, source set, and language/ODR semantics, can a target-specific whole grouping constructor improve compile CPU/RSS/parallelism while preserving stock target artifacts beyond CMake's current batch/group and exclusion rules?

Same-object endpoint: same target source semantics and generated build graph. Full cost: configure/generation, unity-source bytes, compiler CPU/RSS, object/link output, failure/rebuild behavior. Minimum falsifier: the candidate is only grouping/bin-packing, an exposed batch-size setting, or changed source semantics.
