# Candidate-grade deep reviews

## CLOUD-EBS-TAIL — `DROP_DIRECT_ABSORPTION`

The exact object is a cloud block-store I/O trace with identical completion and fairness semantics. The objective shift is genuine—P99999 tail under burst and underloaded regimes—but the official NSDI record already names the complete native construction: dual-bucket throttling for burst fairness plus priority I/O scheduling that separates I/O from unrelated event-loop work. The fair union is that construction and the stated deployed comparison family under the same observed I/O state. A prospective “tail-aware joint action” has no action-divergence witness beyond changing throttling or priority policy, which is selector/controller work. Full cost would include admission, queueing, event-loop CPU, storage/network work and tail distribution. A finite Stage-A killer, if it were admitted, would replay 20–50 trace segments through the native semantics and require a new action to remain outside that union; it fails before admission because no such action is frozen. This is a direct-collision drop, not a readiness judgment.

## MDK-SLO-CAPACITY — `DROP_DIRECT_ABSORPTION`

The exact object is an unchanged job execution set with the action of reclaiming memory to admit further jobs while respecting the same performance SLO. MDK explicitly identifies this as a flipped objective, provides an offline optimal policy, Memory Performance Curves, efficient curve construction, and derived data-center policies. Thus the strongest union includes the objective-aware policy/curve construction, not the former fixed-memory OPT/MRC baseline. A putative “joint SLO/capacity reclamation” is semantically the already-present action unless it specifies a new policy/representation with an independent guarantee. Full cost comprises observation, reclamation/restoration, SLO loss, memory saved and additional jobs. A finite killer would compare 20–50 fixed trace windows to the offline MDK oracle at an identical SLO; no union-external atomic action exists to test. Drop is direct absorption only.

## KAREUS-TIME-ENERGY — `DROP_DIRECT_ABSORPTION`

The function is the same training computation/model result. The atomic action is a joint kernel schedule and frequency schedule under either a fixed training-time or fixed-energy constraint. Kareus already makes the dynamic/static-energy coupling explicit and supplies a partitioned, multi-pass multi-objective constructor. Its fair union includes that constructor, its contemporaneous baselines, the same kernel information, DVFS transitions, both energy components and total training time. Renaming another search over schedule/frequency pairs is ordinary configuration/opaque optimization, not a residual N2. A finite killer would use 20–50 fixed workload instances and reject an action reproducible by Kareus’s feasible schedule/frequency space. This fails the action-gap certificate now, not due to unavailable hardware, source, result, or AI capability.

## JVMALLOC-MOBILE-ENERGY — `DROP_DIRECT_ABSORPTION`

The function is same allocator correctness for allocation/free, with nonblocking soft-real-time behavior and equivalent memory safety. jwmalloc's native construction already jointly provides uniform slab pooling, a closed sibling-tree fragment structure, two-buffer lifetime tracking, and weak-memory bounded-model-check verification. The fair union therefore contains the complete allocator data structure and its safety condition, not merely jemalloc parameter choices. A proposed energy/memory/tail allocator needs a fresh atomic representation or proof beyond this union; none was specified. Full cost is allocation/free latency, instructions, power, footprint, fragmentation, cross-size reuse, and verification. A finite Stage-A killer would model-check small allocation traces and replay 20–50 natural mobile allocation traces with identical semantics; without an action divergence it cannot proceed. Direct absorption is the sole disposition.
