# Research-question candidate

## Primary RQ — RQ98-01

For a fixed Java `Phaser` phase program, registered-party set, phase/termination endpoint and happens-before contract, is there a non-generic whole-hierarchy construction that improves CPU, RSS or phase latency without changing registration, advance, release or termination semantics?

The RQ is viable only if the construction is distinct from selecting a tiering shape, threshold or ordinary scheduling policy already offered by the native abstraction.
