# Comparator separation matrix

This matrix is a claim-ceiling audit using the frozen primary and confirmation Stage 0 source reviews.  It does not assert current absence from any project, nor does it treat a generic extension hook as proof of a scientific gap.

| Comparator / current union facet | Same-object relevance | What a valid revised mechanism had to add | Static revision finding |
| --- | --- | --- | --- |
| vLLM FCFS, priority, `scheduler_cls`, batch/KV controls | Direct native deployment substrate | Whole online algorithm, not merely a custom class, scalar rank, or setting | The 25-call bound defeats every legal class implementation before algorithm choice. |
| VTC | LLM-service token fairness / service bound | Complete-call progress-state reservation and frozen arrival-relative fairness | No such candidate can satisfy the frozen all-state cap. |
| DLPM / D2LPM | LLM locality and fair scheduling | Same OpenHands call semantics plus target-specific public-progress guarantee | Locality manipulation cannot remove the capacity lower bound. |
| Justitia | Task-parallel LLM-agent scheduling, near vLLM deployment | Non-generic per-call mechanism and guarantee under fixed agent object | Existing scheduling domain is a strong subtractor; no surviving mechanism exists. |
| SAGA | Workflow/agent scheduling with fairness and cache considerations | Same complete nonpreemptive call action without workflow/retry/reconfiguration changes | Different workflow framing does not solve the fixed call-count contradiction. |
| SMetric | Session/turn aware scheduling and locality/load balance | A guarantee beyond session ranking or metric selection | A score or metric is expressly insufficient and cannot satisfy the proof. |
| NVIDIA Dynamo ThunderAgent | Agent execution and tool-boundary control | Same frozen no-pause/no-resume action with distinct complete-call guarantee | Its richer control is outside the frozen action; importing it would be a forbidden action change. |

## Separation conclusion

There is no positive candidate-to-subtractor separation to certify.  An implementation of a progress-aware ranker, aging rule, custom vLLM scheduler, or a composition of the listed techniques would still map the 25 ready calls into batches of at most eight.  Such a proposal is either infeasible under the frozen hard cap or a generic/existing fair-LLM scheduling application.  The revision therefore returns to the pre-registered sentinel rather than renaming a comparator feature as N2.
