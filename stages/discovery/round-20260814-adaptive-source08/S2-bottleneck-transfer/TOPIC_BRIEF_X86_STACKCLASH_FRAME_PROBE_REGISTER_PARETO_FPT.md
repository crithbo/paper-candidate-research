# X86-STACKCLASH-FRAME-PROBE-REGISTER-PARETO-FPT — Joint x86 stack-clash frame, probe and register construction

## 中文摘要

本题固定 x86-64 SysV 的 C/C++ 函数、目标、ABI、程序输出、unwind 要求与 -fstack-clash-protection 的逐页可触达安全不变量。它不是换栈、改 guard 页大小或切换 sanitizer，而是在同一机器函数中，把栈对象/保存寄存器的合法布局、页面探测序列和探测临时寄存器或溢出位置联合作为一个有界构造问题。LLVM 文档表明寄存器分配先引入 spill，随后 prolog/epilog 才在已知栈空间时插入；stack-clash 方案又限制未探测的累计下移。这给出成本迁移到探测与 spill 的机制。当前没有实测结果；Stage 0 应独立攻击该动作是否已被 current union 吸收。

## Research question

对固定函数和相同 stack-clash 安全、ABI、unwind 与程序语义，是否存在一个参数为探测边界数和跨边界 live-range 数的目标特定 FPT/Pareto 构造，联合选择合法 frame/probe/scratch-or-spill 决策，并严格改善当前分配器后接 frame/probe emitter 的组合前沿？

## Canonical research claim package

- Contribution route: N2 target-specific joint algorithm.
- Exact object: fixed x86-64 Linux SysV source/IR, ABI, target features, stack-guard model, observable output, defined-behavior tests and unwind contract.
- Intervention and atomic action: construct a finite state sequence (frame-object placement class, callee-save realization, probe boundary, scratch register/spill realization) for one machine function. Legal states use native frame objects/instructions and preserve the page-by-page probe invariant.
- Information condition: exactly the comparator's MachineIR, liveness, target registers, object sizes/alignments, ABI and guard size; no new profile oracle or source rewrite.
- Candidate guarantee: for bounded w probe boundaries and boundary-crossing live ranges, enumerate the exact Pareto frontier in f(w) poly(n) for prologue/epilogue bytes, probe count, spill/reload cost and frame bytes under the frozen safety and ABI predicates. No claim outside that interface.
- Named fair union: current Clang options + X86 frame lowering/probe emitter + LLVM prolog/epilog insertion + default greedy RA and relevant exposed alternative RA/frame options at equal flags, plus stock assembler/linker.
- Native oracle: stock assembler/linker, ABI/unwind validation, semantic regression tests and small stock probe predicate.
- Full-cost: compile CPU/RSS/temp; generated bytes; frame bytes; probe count; spill/reload instructions; later runtime cost only with natural witness.

## Mechanism hypothesis and competitors

LLVM CodeGenerator documents that RA introduces spills and that prolog/epilog insertion occurs after stack space is known. The official stack-clash design specifies page-sized allocation/probe ordering and an asynchronous-signal constraint. Competitors: (1) current RA plus frame lowering realizes every point; (2) it is only option selection; (3) any gain breaks ABI/unwind/probe semantics; or (4) it is generic packing. Any of these is a Stage-A stop predicate.
