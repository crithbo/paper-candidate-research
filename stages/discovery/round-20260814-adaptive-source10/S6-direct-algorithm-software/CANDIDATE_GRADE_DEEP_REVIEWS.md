**Exact object and oracle.** Fix a distributed protocol, its transitions and safety condition.  A candidate must emit invariants accepted by the artifact's Dafny verifier and preserve the same theorem, rather than alter the protocol, use a weaker check, or choose a verifier backend.

**Current source/union.** The OSDI 2025 first-party artifact states that Basilisk factors distributed-protocol invariants into subclasses of Regular Invariants and automatically generates a set strong enough to form the inductive invariant.  The current source exposes Basilisk implementation within its DafnyCore fork and protocols/scripts; the artifact checks all evaluated protocols through the Dafny verifier.  This is the relevant native producer/checker union for the stated action.

**Two-plan witness.** For a protocol with two independently parameterized regular invariant classes, two legal generated sets can retain separate predicate clauses or share their common transition-independent clause; both are checked under the same theorem.  That representation divergence is legal but does not itself yield a non-generic guarantee.

**Strong subtraction and decision.** A proposed joint dependency/taxonomy constructor is the OSDI paper's exact mechanism.  After subtracting it, a new idea reduces to generic clause minimization, SMT/constraint synthesis, or proof scheduling.  No target-specific parameter/theorem that escapes those kernels was identified.  `STRUCTURAL_DROP__PRIMARY_WHOLE_INVARIANT_CONSTRUCTOR_DIRECTLY_ABSORBS`.

**Natural route/full cost/falsifier.** The artifact's sixteen distributed protocols are the natural formal carrier; fidelity would check Dafny acceptance and theorem preservation, charging generation, verifier CPU/RSS/temp and invariant artifact size. A finite falsifier is one protocol whose candidate taxonomy is already generated by current Basilisk or collapses to generic clause minimization. No run was made.

## D2 — Arrival instruction-selection verification construction

**Exact object and oracle.** Fix compiler IR, authoritative ISA semantics, selected instruction sequence and observable behavior.  The stock oracle is Arrival's semantics-based verification; a candidate cannot change ISA, program behavior, or substitute testing for the verifier.

**Current source/union.** The OOPSLA 2025 primary paper presents Arrival as open source and frames its target as verification of a production compiler backend using authoritative ISA semantics.  Its native construction is a verification/certificate path around instruction-selection results; current source is the first-party `mmcloughlin/arrival` project.  Bounded review does not assert an absence of any current check.

**Two-plan witness.** Two instruction sequences can implement the same IR operation under the authoritative ISA semantics while requiring distinct proof obligations/certificate decompositions.  This is a legal verifier-backed plan divergence.

**Strong subtraction and decision.** The prospective “joint selection plus certificate planner” would have to be distinct from existing instruction selection and Arrival's verification construction.  No source-supported target-specific action or guarantee was found: joint proof selection is generic proof search/certificate scheduling, while a selection improvement changes the compiler backend rather than the verified-construction object. `STRUCTURAL_DROP__GENERIC_PROOF_SEARCH_OR_CHANGED_BACKEND_OBJECT`.

**Natural route/full cost/falsifier.** A source-pinned compiler backend test corpus can supply programs; equivalence is Arrival verification plus executable semantics. Full cost would include selection, verification, proof artifacts, CPU/RSS/temp and code size. The fastest falsifier is a same-IR witness where the alleged action either changes selection semantics or is a generic proof-search choice. No run was made.
