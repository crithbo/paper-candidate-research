## Deep review: OpenTelemetry temporal aggregation

**Exact object:** fixed OTLP metric event semantics, instrument kind, resource/scope/attribute identity and exporter/consumer protocol. A legitimate result would need a natural immutable trace set, a pre-registered regime law after controlling producer resets, cardinality, clock/window alignment and overlap, and a non-controller correction that changes an availability/capacity conclusion while retaining all events and full telemetry cost.

The official data model already specifies delta/cumulative temporality, timestamps, overlap handling, single-writer corrective reasoning, temporality conversions and spatial/temporal reaggregation. The metrics specification further treats views and aggregation choice as configuration. Thus the presently named intervention is a pre-existing semantic transform or configuration choice, rather than a union-external action. **Disposition:** `DROP__CURRENT_UNION_ABSORPTION`; this is not based on missing data or implementation.

## Deep review: Cargo timing-characterization

**Exact object:** fixed Cargo/rustc release, crate graph, targets, build profile and emitted artifact semantics. A later characterization paper would have to freeze public commit-to-commit timing artifacts, distinguish Cargo job-server availability from rustc internal concurrency, and show a stable confound-controlled law that changes a non-controller build decision with compilation CPU/RSS/temp/artifact/cache cost charged.

Current official documentation says `--timings` produces human-consumption HTML and does not show compiler-internal concurrency. This supports a bounded future evidence route but does not establish a law, natural carrier, or correction action. **Disposition:** `NOT_ADMITTED_UNFROZEN`, not a scientific negative about a missing implementation/result/resource.

`COMPLETE_ZERO_PROPOSALS`. No brief is emitted. Reopening requires a new immutable natural carrier and a law-to-decision correction outside current configuration, stream transforms, benchmark statistics, controllers, dashboards, or maintenance.
