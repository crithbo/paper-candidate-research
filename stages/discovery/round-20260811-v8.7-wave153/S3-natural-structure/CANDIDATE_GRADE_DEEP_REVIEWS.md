# CANDIDATE_GRADE_DEEP_REVIEWS — Wave153

## DEEP-153-01 — PubChem graph substructure: `DROP`

- **Exact object/function/oracle.** Input is a query molecular graph plus the PUG-REST structure-search options; output is precisely the returned CID set. PUG-REST documents `substructure`/`superstructure` and synchronous `fastsubstructure`/`fastsuperstructure`, accepts SMILES/SMARTS/InChI/SDF/CID inputs, and exposes options including isotope, charge, ring, bond/aromatic, hydrogen, stereo, `MaxSeconds`, `MaxRecords`, and prior-result restrictions.
- **Natural carrier and condition.** PubChem compound graphs are a public natural carrier. The proposed condition, computable from the same query, is bounded cycle rank of its block-cut tree. This does not change output quality: it would still return the same CIDs under the same flags.
- **Proposed N2 and minimal divergence witness.** A whole constructor would decompose the query on articulation blocks and combine exact embeddings via an FPT DP. The intended witness is a ring/bridge query where the DP's join state spans two blocks rather than choosing an API configuration.
- **Current strongest same-information union / current reality.** Frozen official PUG-REST documentation (current page crawled 2026-08-11) already offers the exact structure-search task, both standard and fast operations, with the listed semantic controls. The candidate's output and information condition are therefore already represented by the deployed union; there is no honest evidence that a changed internal DP is an action-gap rather than an unobservable reimplementation of the same native constructor. Adverse evidence is the API's explicit `fastsubstructure` endpoint and its full option catalogue, including non-default flags.
- **Six-dimensional residual audit.** Decision rule: same CID membership predicate; information: same query/flags; resource: server implementation is an allowed current baseline action; quality: same native membership semantics; full cost: proposed would need query preprocessing plus search, while baseline exposes full request work; generalization/no-gain: no externally distinguishable guarantee or output remains.
- **Latest collision.** Current official PUG-REST specification and tutorial are direct same-object collisions, not merely a paper-title similarity.
- **Finite StageA killer (not run).** On a small public CID/query set, compare exact CID sets for representative ring/bridge queries under every relevant PUG flag; if equal (the required native semantics), no claim-bearing residual exists. This cannot rescue the proposal because the present action-gap is already absent.
- **Structural paper potential / readiness.** `BELOW_Q2_STOP` due direct same-object action absorption, not due missing implementation, results, resources or AI readiness.

## DEEP-153-02 — Rfam covariance-model alignment: `NOT_ADMITTED_UNFROZEN`

- **Exact object/function/oracle.** Candidate object would be fixed Rfam family CM + sequence, producing the exact CM alignment/score under frozen Infernal semantics. Rfam 15.1 contains 4,227 families, each represented by alignments, consensus secondary structures and CMs; its official build documentation says Rfam builds CMs with Infernal, searches Rfamseq and uses `cmalign` to add hits to the SEED/FULL alignment.
- **Natural condition and candidate N2.** The proposed same-information predicate is a bound on pathwidth/branching of the supplied pair annotation. A nontrivial candidate action would be a parameterized exact CM DP that eliminates unreachable paired states while preserving the native CM optimum; witness would be a branching structure whose joint paired-state elimination cannot be described as a threshold or model choice.
- **Why no action-gap certificate.** The documentation establishes current CM construction/search/alignment, but it does not freeze the exact Infernal scoring/version/configuration, whether the proposed state elimination is outside its DP implementation, or a first-party same-object executable baseline union. Treating “Infernal exists” as proof of absorption would be improper; treating its unknown implementation as a gap would be equally improper.
- **Six-dimensional audit.** Decision, information and native quality are provisionally same only if an exact CM configuration is frozen; complexity/full-cost cannot then be compared; generalization/no-gain is unknown. Hence no exact action divergence is certified.
- **Latest collision/current reality.** Rfam current release and current official build documentation are recorded; they are contrary evidence to an absence claim and require source/config inspection before any future admission.
- **Finite StageA killer (not run).** Freeze one public family, Infernal release/config and a handful of SEED/FULL sequences; construct the claimed state transition relation and prove either (a) bit-exact equality to the native CM oracle or (b) a counterexample. Failure to freeze the oracle/action relation within 72 hours is a no-admission result, not a scientific STOP.
- **Disposition.** `NOT_ADMITTED_UNFROZEN`; no brief, tier or negative inference from missing implementation/readiness.

## DEEP-153-03 — TreeBASE agreement constructor: `NOT_ADMITTED_UNFROZEN`

- **Exact object/function/oracle.** Proposed object is a pair of deposited phylogenetic trees over frozen shared taxa and a specified maximum-agreement-tree output convention. TreeBASE publicly serves phylogenetic trees/data matrices and provides NEXUS, NeXML, Newick and JSON access.
- **Natural condition and candidate N2.** A same-input disagreement graph on common taxa may have bounded connected components; a complete FPT DP could assemble maximum exact agreement components. The smallest intended divergence witness is two trees with two independent discordant clades requiring a joint boundary state, not a tree-order heuristic.
- **Why no action-gap certificate.** No official current tree-comparison oracle, tie convention, executable algorithm union or source/config was established. A generic maximum-agreement-subtree/ILP wrapper would violate the assignment; an unfrozen DP cannot satisfy the same-object/fidelity gate.
- **Six-dimensional audit.** Decision rule and quality depend on the missing output convention; information and natural input would be same; complexity/full-cost and generalization/no-gain cannot be compared until the strongest union is identified.
- **Latest collision/current reality.** TreeBASE's current public data/API support the carrier but not the required algorithm-union assertion. This is recorded as unresolved evidence, not an absence claim.
- **Finite StageA killer (not run).** Select two small downloadable trees and freeze a canonical maximum-agreement-tree checker/tie rule plus one executable current solver; show the proposed recurrence returns exactly that oracle for all candidate decompositions. If those pieces cannot be frozen within 72 hours, retain no proposal.
- **Disposition.** `NOT_ADMITTED_UNFROZEN`; no brief, no tier assertion and no negative inference from absent implementation.
